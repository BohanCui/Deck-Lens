
# 模式：内部汇报
**适用场景：** 向本组织领导、管理层或跨部门负责人汇报

受众已经有组织背景。他们很忙。他们想先听结论，再听理由。不要让他们坐等十分钟铺垫之后才知道你想说什么。

本模式遵循**金字塔原则**：先给答案，再给支撑。

---

## 八段内部汇报结构

| # | 环节 | 目的 |
|---|------|------|
| 1 | **执行摘要** | 一张幻灯片。说清楚：现状是什么、你的建议是什么、预期结果是什么。后面所有内容都是支撑这一页的——领导看完这一页就应该知道你在请示什么。 |
| 2 | **背景与来龙去脉** | 简洁、中立地说明这个议题为何被提上日程。什么触发了这次审视？范围边界是什么？ |
| 3 | **问题定义** | 客观描述问题。不追责，不情绪化。尽量用数据支撑。当前状况带来了什么成本或影响？ |
| 4 | **现有做法与不足** | 目前这件事是怎么处理的——由你的团队、另一个部门还是某个现有系统？具体哪里没做好？避免把这页做成批评，定性为客观评估。 |
| 5 | **建议方案** | 你的建议是什么，如何落地？先说它能带来什么结果，再描述关键组成部分。除非受众需要细节，否则保持高层次。 |
| 6 | **依据与验证** | 为什么他们应该相信这行得通？试点结果、对标数据、内外部可比案例、专家意见。这里是你建立可信度的地方。 |
| 7 | **资源需求与时间线** | 实现这个方案需要什么？预算、人力、工具、审批、时间节点。要具体——模糊的请求只会得到模糊的回应。 |
| 8 | **下一步与请示事项** | 你需要这批受众做什么具体决定或行动？截止时间是什么？一个清晰的请示。如有选项，给出2～3个并标明推荐路径。 |

## 幻灯片数量参考

| 环节 | 张数 |
|------|------|
| 1 执行摘要 | 1 |
| 2 背景与来龙去脉 | 1 |
| 3 问题定义 | 1～2 |
| 4 现有做法与不足 | 1～2 |
| 5 建议方案 | 2～3 |
| 6 依据与验证 | 1～2 |
| 7 资源需求与时间线 | 1～2 |
| 8 下一步与请示事项 | 1 |
| **合计** | **约9～14张** |

## 语气要点
- 正式但直接——不喊口号，不表演热情
- 先给结论，不要带着领导一起"发现"答案
- 避免"我们为此付出了很多努力"式的叙述——聚焦结果和影响
- 对现有做法保持中立：做差距分析，不做批斗会
- 如有附件材料（详细数据、组织架构、完整财务），放在主体之后，不要打乱主线节奏
- 请示事项必须明确："请批准推进"、"请于X日前给出决定"
